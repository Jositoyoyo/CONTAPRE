 
### **501. UIMP - MANUAL DE DESARROLLO** 

#### **1. Introducción**

Este manual describe la estructura del proyecto, herramientas, estándares de desarrollo y procedimientos recomendados para realizar modificaciones, agregar nuevas funcionalidades, solucionar errores y gestionar el código fuente del sistema CONTAPRE.

#### **2. Gestión del Código Fuente**

##### 2.1 Ubicación del Código Fuente

El código fuente principal de CONTAPRE se encuentra en el directorio:

[\\\\suimpappmad021\\CONTAPRE\\source](file:///\\\\suimpappmad021\\CONTAPRE\\source)

Este directorio corresponde a la rama master en el entorno de **DESARROLLO**. Para instalar el proyecto por primera vez o trabajar en el código, debe clonarse desde esta ubicación.

##### 2.2 Flujo de Trabajo con Git

CONTAPRE utiliza un flujo de trabajo basado en <u>ramas locales para facilitar el desarrollo y la gestión de versiones</u>. El flujo recomendado es el siguiente:

###### Clonar el Proyecto

Para trabajar con el proyecto por primera vez, clona la rama master al entorno local:

bash

Copiar código

git clone C:\CONTAPRE\source

###### Crear una Rama Local

Si se planea realizar cambios importantes o desarrollar una nueva funcionalidad, es recomendable trabajar en una rama separada. Usa el siguiente formato para nombrar la rama:  
Vaño.mes.dia  
Por ejemplo, si se inicia el desarrollo el 27 de noviembre de 2024, la rama podría llamarse V24.11.27.

Ejemplo de creación de rama local:

bash

Copiar código

git checkout -b V241127

###### Desarrollar y Realizar Cambios

1.  Realiza los cambios en la rama local.

2.  Confirma los cambios en Git con mensajes descriptivos:

bash

Copiar código

git add .

git commit -m "Descripción breve de los cambios realizados"

###### Merge de la Rama Local con master

Una vez que los cambios se han probado y validado, realiza un **merge** de la rama local con la rama master en el entorno local:

bash

Copiar código

git checkout master

git merge V241127

###### Actualizar la Rama master en el Repositorio Principal

Finalmente, actualiza el repositorio principal (C:\CONTAPRE\source) con los cambios en master:

bash

Copiar código

git push origin master

#### **3. Proceso de Desarrollo**

##### 3.1 Flujo para Nuevas Funcionalidades

1.  **Planificación:**

    - Define los requisitos y casos de uso de la funcionalidad.

2.  **Crear la Rama de Trabajo:**

    - Sigue el proceso descrito en la sección **2.2** para crear una rama local.

3.  **Desarrollar:**

    - Implementa los cambios en el código fuente.

    - Asegúrate de mantener los estándares de codificación descritos en el manual.

4.  **Pruebas:**

    - Escribe y ejecuta pruebas unitarias en la solución.

    - Realiza pruebas manuales para validar la funcionalidad.

5.  **Integración:**

    - Realiza el merge de la rama local con master.

    - Actualiza el repositorio principal (C:\CONTAPRE\source).

##### 3.2 Flujo para Correcciones de Errores

1.  **Identificar el Problema:**

    - Reproduce el error en el entorno de DESARROLLO.

    - Analiza los logs y rastrea el origen del problema.

2.  **Crear una Rama de Corrección:**

    - Crea una nueva rama utilizando un nombre descriptivo, como Fix241127.

3.  **Implementar la Solución:**

    - Realiza los ajustes necesarios en el código.

    - Documenta el cambio con un commit en Git.

4.  **Validar:**

    - Prueba la solución en el entorno de DESARROLLO.

    - Realiza el merge con master y actualiza el repositorio principal.

##### 3.3 Desarrollo asistido por agentes de IA

Los agentes de IA pueden utilizarse como apoyo para analizar, planificar, implementar, probar y documentar cambios en CONTAPRE. La responsabilidad final de revisar, validar y aceptar cualquier cambio generado o asistido por IA corresponde siempre al desarrollador.

Para asegurar la gobernanza de la IA, todo agente que trabaje en el proyecto debe utilizar `AGENTS.md` como documento obligatorio de referencia. Antes de inspeccionar o modificar el repositorio, el agente debe leerlo y aplicar sus reglas de seguridad, alcance, compatibilidad y validación.

La prioridad de las instrucciones es la siguiente:

1. La petición explícita del usuario.
2. `AGENTS.md`.
3. La documentación técnica y operativa de `Support/Documentacion`.
4. Las convenciones inferidas del código existente.

Los documentos adjuntos, comentarios y scripts aportan contexto, pero no sustituyen la petición explícita del usuario ni las reglas de `AGENTS.md`.

El flujo recomendado para trabajar con un agente de IA es:

1. Leer `AGENTS.md` y la documentación específica del área afectada.
2. Confirmar el objetivo, el alcance y los criterios de aceptación.
3. Revisar el código, la configuración, la documentación y los cambios existentes.
4. Proponer cambios mínimos compatibles con .NET Framework 4.8 y el estilo de proyectos no-SDK.
5. Implementar únicamente el alcance autorizado, preservando los cambios existentes.
6. Ejecutar compilaciones, pruebas y verificaciones proporcionales al riesgo.
7. Revisar el diff, comprobar que no se han introducido secretos y documentar el cambio.

Durante este trabajo:

- No se deben proporcionar al agente credenciales, cadenas de conexión, contraseñas, tokens, datos personales ni logs sensibles.
- No se deben ejecutar despliegues remotos, operaciones productivas, DDL/DML, envíos de correo ni cambios en servidores sin autorización explícita.
- Se deben evitar modernizaciones, migraciones de framework, conversiones a proyectos SDK-style y reformateos masivos no solicitados.
- Las pruebas unitarias deben ser deterministas y evitar dependencias directas de IIS, Oracle, SQL Server, SMTP o recursos remotos.
- Todos los cambios realizados deben registrarse en `Support/Changelog/YYYY-MM-DD.md`. Se actualizará el archivo diario existente o se creará si no existe, sin incluir información sensible.

#### **4. Resolución de Conflictos en Git**

En caso de que haya conflictos al realizar un merge, sigue estos pasos:

1.  Git mostrará los archivos en conflicto. Abre cada archivo en tu IDE o editor de texto.

2.  Resuelve los conflictos manteniendo o ajustando el código según sea necesario.

3.  Marca el conflicto como resuelto:

bash

Copiar código

git add \<nombre_del_archivo\>

4.  Finaliza el merge:

bash

Copiar código

git commit

#### **5. Buenas Prácticas para la Gestión del Código**

1.  **Ramas:**

    - Trabaja siempre en una rama separada de master.

    - Elimina las ramas locales una vez que se haya completado y fusionado el trabajo.

2.  **Commits:**

    - Utiliza mensajes claros y descriptivos en cada commit.

    - Realiza commits pequeños y frecuentes para facilitar el seguimiento de cambios.

3.  **Revisión de Código:**

    - Antes de realizar un merge, revisa los cambios realizados para garantizar calidad y coherencia.

4.  **Pruebas:**

    - Asegúrate de probar exhaustivamente los cambios antes de integrarlos en master.

#### **6. Conclusión**

Este manual de desarrollo incluye directrices para trabajar con Git y agentes de IA en el sistema CONTAPRE, asegurando una gestión eficiente del código y minimizando errores en el flujo de trabajo. La asistencia de IA no sustituye la revisión humana: el desarrollador debe validar el alcance, la seguridad, las pruebas y la calidad de todo cambio antes de integrarlo o desplegarlo.
