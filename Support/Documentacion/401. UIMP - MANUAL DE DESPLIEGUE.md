## 1. Introducción

Este manual describe el flujo actual para compilar, probar y desplegar CONTAPRE en los entornos local, desarrollo y producción.

La solución se mantiene en:

```text
C:\inetpub\apps\CONTAPRE
```

El proceso utiliza los scripts de `Support\Deploy`. No se utiliza una carpeta intermedia como `C:\CONTAPRE\publicar`, ni los antiguos scripts `DeployApp.ps1` o la carpeta `Utilities`.

Los scripts de despliegue tienen efectos externos. Deben ejecutarse únicamente con autorización explícita y después de revisar el destino, la configuración y el alcance de los archivos afectados.

## 2. Aplicación y configuraciones

- Aplicación ASP.NET Web Forms sobre .NET Framework 4.8.
- Solución: `Dimatica.ContaPre.sln`.
- Configuraciones de compilación utilizadas:
  - Local: `Development`.
  - Desarrollo: `Development`.
  - Producción: `Release`.
- Plataforma habitual: `Any CPU`.
- Proyecto web: `Dimatica.ContaPre.Presentation`.
- Perfil de desarrollo: `DESARROLLO.pubxml`.
- Perfil de producción: `PRODUCCION.pubxml`.

La configuración sensible permanece en los archivos de configuración de la aplicación y sus transformaciones. No se deben copiar credenciales, cadenas de conexión, contraseñas ni tokens a este manual, a commits o a mensajes de operación.

## 3. Scripts disponibles

Los scripts se encuentran en `Support\Deploy`:

| Script | Uso |
| --- | --- |
| `StartLocal.ps1` | Reconstruye la solución en `Development` y levanta IIS Express en `http://localhost:54234/`. |
| `DeployDesarrollo.ps1` | Compila y publica directamente en el servidor de desarrollo. Solicita confirmación, limpia los logs remotos y publica únicamente `ClearLogs.ps1` desde `Support\Deploy`. |
| `DeployProduccion.ps1` | Compila y publica directamente en producción. Pregunta si se desea crear un backup ZIP antes de publicar. |
| `RollbackProduccion.ps1` | Restaura en producción el contenido exacto de un backup ZIP seleccionado por nombre. |
| `ClearLogs.ps1` | Limpia los logs de la instalación local configurada y solicita confirmación. Se publica de forma separada en desarrollo. |
| `OpenIISAndFolder.ps1` | Abre el administrador de IIS y la carpeta local configurada. No compila ni publica la aplicación. |

Los archivos de `Support\Deploy` distintos de `ClearLogs.ps1` no se copian como parte del despliegue de desarrollo.

## 4. Pre-requisitos

Antes de ejecutar cualquier script:

1. Confirmar que el código que se va a desplegar corresponde a la rama y revisión autorizadas.
2. Revisar los cambios pendientes y comprobar que no contienen secretos ni archivos generados innecesarios.
3. Disponer de PowerShell y de una instalación compatible de Visual Studio/MSBuild.
4. Tener permisos para compilar localmente y, en los despliegues remotos, para acceder al destino correspondiente.
5. Confirmar que la configuración de cada entorno es la adecuada y que no se van a utilizar credenciales de otro entorno.
6. Notificar a los usuarios cuando el despliegue pueda afectar a la disponibilidad de la aplicación.

No se deben ejecutar publicaciones, limpieza de logs, backups remotos ni borrados remotos como parte de una verificación rutinaria sin autorización.

## 5. Ejecución local

La ejecución local sirve para validar la compilación y levantar la aplicación sin modificar IIS del sistema ni ningún servidor remoto.

Desde la raíz del proyecto:

```powershell
Set-Location 'C:\inetpub\apps\CONTAPRE'
.\Support\Deploy\StartLocal.ps1
```

El script:

- Localiza automáticamente `Dimatica.ContaPre.sln`.
- Localiza `MSBuild.exe` e `iisexpress.exe` en las instalaciones habituales.
- Comprueba el proyecto web, el archivo `.vs\Dimatica.ContaPre\config\applicationhost.config` y el puerto `54234`.
- Ejecuta un `Rebuild` en configuración `Development`.
- Inicia el sitio `Dimatica.ContaPre.Presentation` mediante IIS Express.

La aplicación queda disponible en:

```text
http://localhost:54234/
```

El proceso permanece en primer plano. Se puede detener con `Ctrl+C` o con la opción de parada que muestra IIS Express. Si el puerto está ocupado, el script informa del conflicto y no detiene el proceso existente.

Este flujo no realiza backups, limpieza de logs, publicación remota, copia de `ClearLogs.ps1` ni cambios en IIS del sistema.

## 6. Despliegue en desarrollo

### 6.1 Destino y comportamiento

El despliegue se realiza directamente en:

```text
\\suimpappmad021\C$\inetpub\wwwroot\CONTAPRE
```

El script `DeployDesarrollo.ps1` utiliza:

- Configuración `Development`.
- Perfil `DESARROLLO.pubxml`.
- Publicación directa mediante MSBuild.
- Sin carpeta de staging.
- Sin backup automático.

Antes de modificar el destino, solicita confirmación `S/N`. Cualquier respuesta distinta de `S` cancela la operación sin realizar cambios remotos.

### 6.2 Ejecución

Con autorización y desde la raíz del proyecto:

```powershell
Set-Location 'C:\inetpub\apps\CONTAPRE'
.\Support\Deploy\DeployDesarrollo.ps1
```

Después de confirmar:

1. Se eliminan los archivos existentes dentro de la carpeta `Logs` del destino remoto.
2. Se reconstruye y publica la aplicación en el destino directo.
3. Se verifica que exista `Web.config` en el destino.
4. Se copia únicamente `Support\Deploy\ClearLogs.ps1` a la raíz del destino como `ClearLogs.ps1`.
5. Se compara el hash SHA-256 del archivo de origen con el archivo publicado.

No se copian `DeployDesarrollo.ps1`, `DeployProduccion.ps1`, `StartLocal.ps1`, `OpenIISAndFolder.ps1` ni otros archivos de `Support\Deploy`.

## 7. Despliegue en producción

### 7.1 Destino y comportamiento

El despliegue se realiza directamente en:

```text
\\suimpappmad041\C$\inetpub\wwwroot\CONTAPRE
```

El script `DeployProduccion.ps1` utiliza:

- Configuración `Release`.
- Perfil `PRODUCCION.pubxml`.
- Publicación directa mediante MSBuild.
- Eliminación de los archivos existentes definida por el perfil de publicación.

### 7.2 Versión de la aplicación

La aplicación lee la versión que muestra el login desde `Dimatica.ContaPre.Presentation\JSON.json`. El archivo contiene las propiedades de texto `version` y `releaseDate`; la versión inicial es `20260826` y la fecha inicial `2026-08-26`. En cada despliegue de producción completado, la versión aumenta en una unidad y `releaseDate` se actualiza a la fecha local del despliegue en formato `yyyy-MM-dd`.

El script valida el JSON, su contador y la fecha existente antes del backup y la publicación. Prepara la nueva versión y fecha para que se incluyan en la publicación y comprueba que el destino contiene ambos valores. Si la publicación o la verificación falla, restaura el contenido local anterior. Un archivo ausente, un JSON no válido o un contador o fecha inválidos detiene el proceso antes de modificar el destino.

En el login, la fecha se muestra como ayuda contextual (`title`) al situar el cursor sobre el número de versión.

### 7.3 Backup opcional

Antes del backup y de la publicación, el script pregunta si se desean ejecutar las pruebas unitarias del proyecto `Dimatica.ContaPre.PresentationUnitTest`.

Si se responde `S`, reconstruye el proyecto en configuración `Debug` y ejecuta el ensamblado mediante `vstest.console.exe`. Si la reconstrucción o cualquier prueba falla, o no están disponibles el proyecto, el ejecutor o el ensamblado esperado, el despliegue se detiene antes de crear el backup o publicar. Si se responde `N` o cualquier otra opción, se omiten las pruebas y el proceso continúa.

Después de las pruebas opcionales, el script pregunta si se desea crear un backup.

Si se responde `S`:

1. Se comprueba que el sitio IIS actual sea accesible.
2. Se crea la carpeta de backups si no existe:

   ```text
   \\suimpappmad041\CONTAPRE\backups
   ```

3. Se comprime el contenido actual del sitio en un ZIP con formato:

   ```text
   backup_ddMMyyyyHHmm.zip
   ```

4. Se mantienen las rutas relativas del sitio, sin añadir una carpeta raíz adicional.
5. Se verifica que el ZIP se pueda abrir y que contenga entradas.

Si ya existe un ZIP con el mismo nombre, el backup se aborta para evitar sobrescribirlo. Si el backup solicitado falla o no se puede verificar, el despliegue se detiene y no se publica la aplicación.

Si se responde `N` o cualquier respuesta distinta de `S`, no se crea ningún backup y el despliegue continúa.

El backup cubre los archivos actuales del sitio IIS. No sustituye a un procedimiento independiente de backup de bases de datos.

### 7.4 Ejecución

Con autorización y desde la raíz del proyecto:

```powershell
Set-Location 'C:\inetpub\apps\CONTAPRE'
.\Support\Deploy\DeployProduccion.ps1
```

El script solo inicia la publicación después de completar correctamente el backup solicitado. Al finalizar comprueba que existan `Web.config` y `JSON.json` en el destino, y que la versión y la fecha publicadas coincidan con los valores calculados.

### 7.5 Reversión mediante backup

Para restaurar una versión anterior del código se utiliza `RollbackProduccion.ps1`. El script no compila, no ejecuta MSBuild, no modifica bases de datos, no cambia la configuración de IIS y no detiene automáticamente el pool de aplicaciones.

Con autorización y desde la raíz del proyecto:

```powershell
Set-Location 'C:\inetpub\apps\CONTAPRE'
.\Support\Deploy\RollbackProduccion.ps1
```

El procedimiento es el siguiente:

1. El script comprueba que se ejecuta en el equipo `suimpappmad041` y que la carpeta de backups y el destino de produccion usan ese host; si no, se detiene antes de acceder a esas rutas.
2. Introducir el nombre exacto del ZIP existente en `\\suimpappmad041\CONTAPRE\backups`, por ejemplo `backup_280920261118.zip`.
3. El script valida que el nombre sea un archivo simple `.zip`, que exista y que el archivo se pueda abrir.
4. Se validan las entradas del ZIP y se rechazan rutas inseguras o un backup sin `Web.config` en la raíz.
5. Se muestran el backup y el destino `\\suimpappmad041\C$\inetpub\wwwroot\CONTAPRE`.
6. Se solicita una confirmación final antes de modificar producción. Cualquier respuesta distinta de `S` cancela la operación.
7. El ZIP se extrae primero en una carpeta temporal local.
8. Se sincroniza el contenido extraído con el destino usando un reemplazo exacto: también se eliminan archivos que no existan en el backup.
9. Se verifica el resultado, incluyendo la estructura de archivos y la presencia de `Web.config`.
10. Se elimina la carpeta temporal al finalizar.

El rollback no crea automáticamente un backup adicional del estado actual. Antes de ejecutarlo se debe confirmar que el backup seleccionado es el correcto y que existe autorización para reemplazar todo el contenido del sitio. Solo se restauran archivos de la aplicación; las bases de datos y otros servicios requieren procedimientos independientes.

## 8. Validación posterior

Después de un despliegue autorizado:

1. Confirmar que el script finalizó sin errores.
2. Comprobar que la aplicación responde en la URL del entorno correspondiente.
3. Validar el acceso y el inicio de sesión con una cuenta de prueba autorizada.
4. Ejecutar una comprobación funcional básica de los módulos afectados.
5. Revisar los logs de aplicación y del servidor sin copiar datos sensibles al informe.
6. Confirmar que el pool de aplicaciones de IIS está iniciado y utiliza la configuración esperada.

En producción, registrar si se creó backup, el nombre del ZIP y el resultado de la verificación. No registrar credenciales ni cadenas de conexión.

## 9. Resolución de problemas

| Problema | Acción |
| --- | --- |
| No se encuentra la solución, el perfil o el proyecto web | Ejecutar el script desde el árbol del proyecto correcto y comprobar que los archivos existen. |
| No se encuentra MSBuild | Instalar o habilitar las herramientas de compilación compatibles y revisar las rutas de Visual Studio detectadas por el script. |
| El puerto local `54234` está ocupado | Cerrar o revisar el proceso que lo utiliza. `StartLocal.ps1` no lo detiene automáticamente. |
| IIS Express no inicia | Revisar permisos, el archivo `applicationhost.config`, el sitio configurado y la salida de IIS Express. |
| El destino remoto no es accesible | Comprobar conectividad, permisos y que la ruta UNC corresponda al entorno autorizado. |
| La confirmación de desarrollo no es `S` | El despliegue se cancela y no se limpian logs ni se modifican archivos remotos. |
| El backup de producción colisiona con otro ZIP | Esperar a otro minuto o conservar el ZIP existente y ejecutar el procedimiento autorizado posteriormente. No sobrescribirlo manualmente. |
| La compilación muestra una advertencia de CodeDom pero termina con código 0 | Registrar la advertencia y revisar el resultado de la aplicación; no confundir una advertencia con un fallo de compilación. |
| La aplicación no refleja los cambios | Revisar el código publicado, `Web.config`, el pool de IIS y la fecha/hash de los archivos afectados. |

## 10. Buenas prácticas

- Usar `StartLocal.ps1` para validar primero la compilación y el comportamiento local.
- Ejecutar los scripts remotos únicamente con autorización explícita.
- Revisar siempre el destino antes de confirmar una operación.
- Mantener separados los entornos de desarrollo y producción.
- No modificar manualmente archivos publicados para corregir una incidencia sin registrar el cambio.
- No incluir secretos, datos personales, logs completos ni cadenas de conexión en documentación o commits.
- Conservar los backups de producción según la política operativa vigente y verificar periódicamente que puedan abrirse.
